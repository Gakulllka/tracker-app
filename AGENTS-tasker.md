## 1. Что это за проект

**BA Assistant** — веб-приложение (клиентский SPA) для автоматизации работы
бизнес-аналитика: генерация технических заданий (ТЗ), тест-кейсов,
BPMN-диаграмм, протоколов и другой документации с помощью ИИ.

Приложение **само генерирует документы** через внешних AI-провайдеров. Оно
целиком работает в браузере, данные хранит в `localStorage` (опционально
синхронизирует в Supabase). Бэкенда своего нет.

### ⚠️ Важно про файлы `*ТЗ*.docx` / сгенерированные ТЗ

В репозитории и в загрузках могут встречаться документы вида «ТЗ на
приложение аналитика», описывающие Next.js / shadcn / Recharts / Server
Actions и т.п. **Это НЕ спецификация этого проекта.** Это примеры **выходного
контента**, который BA Assistant генерирует для пользователей (контекст
«ИИ ТЗ → Промпт для агента»). Не воспринимай их как требования к архитектуре
и не тащи из них стек. Правда — только README и этот файл.

## 2. Технологический стек

| Слой | Технология | Заметки |
|------|------------|---------|
| UI | React 19 + TypeScript | Только функциональные компоненты + хуки |
| Сборка | Vite 8 | Переменные окружения через `import.meta.env` (`VITE_*`) |
| Стили | Tailwind CSS 4 | Утилити-классы + `cn()` из `lib/utils` |
| Роутинг | React Router 7 | Клиентский роутинг. **Не Next.js** |
| AI | OpenAI, Anthropic, Yandex GPT, Z.AI | Только через `lib/ai-providers.ts` |
| Экспорт | `docx`, `pdf-lib`, `xlsx`, `pptxgenjs` | Только через модули `lib/*-export`, `lib/doc-generator` |
| Хранилище | `localStorage` (опц. Supabase) | Только через модули-стораджи в `lib/` |
| i18n | RU / EN | Все тексты через `lib/i18n.tsx` + `translations.ts` |

**Чего в проекте НЕТ (не добавляй без явного запроса):** Next.js, Server
Components / Server Actions, shadcn/ui, Recharts, Redux/Zustand.

**Спец-зависимости и их статус:** `bpmn-js` — уже подключён и используется в `BpmnViewer` (этап 2 BPMN); `mermaid` — **ещё не установлен**, клиентский рендер черновиков BPMN не реализован. Также санкционировано ТЗ:
`iframe` с `sandbox` для рендера HTML-прототипов (модуль «Визуализация ТЗ»);
внешний рендер PlantUML через Kroki / `plantuml.com`. Экспорт XLSX — с
**живыми формулами** в ячейках (модуль «Расчётчик»).

```
│
├── lib/              # ⭐ Ядро логики (см. правило про Service-слой)
│   ├── ai-providers.ts   # Абстракция 4 провайдеров — все вызовы ИИ идут сюда
│   ├── prompts.ts        # Промпты инструментов
│   ├── prompts/          # tz-steps.ts — пошаговая генерация ТЗ
│   ├── tz-template.ts    # Шаблоны ТЗ (12 пресетов, 4 контекста)
│   ├── tz-store.ts       # Хранилище ТЗ (localStorage)
│   ├── tz-export.ts      # Экспорт ТЗ в DOCX/PDF
│   ├── document-store.ts # Общее хранилище документов
│   ├── file-storage.ts   # Файлы пользователя
│   ├── artifact-store.ts # Единое хранилище артефактов (все типы)
│   ├── doc-generator.ts  # Генерация DOCX/PDF/XLSX/PPTX
│   ├── excel-calculator.ts # Excel-калькулятор из ТЗ
│   ├── supabase.ts       # Клиент Supabase (опционально)
│   ├── i18n.tsx / translations.ts # Локализация RU/EN
│   └── utils.ts          # cn() и утилиты
│

```

**Куда что класть:** экраны → `pages/`, визуальные компоненты →
`components/`, логика/состояние → `hooks/`, доступ к данным / ИИ / экспорт /
бизнес-правила → `lib/`.

**Реализовано по ТЗ:** `lib/artifact-store.ts` (единое хранилище
артефактов), `components/input/InputSourceSelector.tsx` (источники входа),
отдельные экраны/редакторы под модули (тест-чеклист, BPMN, протокол,
расчётчик, HTML-прототип) и промпты этих модулей в `lib/prompts/`.

## 4. Правила разработки (соблюдай при любом изменении)

### TypeScript
- Строгая типизация. **Никаких `any`** — если тип неизвестен, используй
  `unknown` или `Record<string, unknown>`.
- Типы держи рядом с модулем или в общем файле типов; не дублируй интерфейсы.

### React
- Только **функциональные компоненты + хуки**. Class-компоненты запрещены.
- Компоненты «тонкие»: JSX и презентация — в `components/`, логика — в
  `hooks/` и `lib/`. Не смешивай бизнес-логику с разметкой.
- Используй корректный JSX (`<>…</>` вместо `React.Fragment` без нужды).
- `useEffect` — только по необходимости, не «на всякий случай».

### Роутинг
- Это **React Router 7**, клиентский SPA. Не используй Next.js-паттерны:
  никаких `app/`-роутов, `use client`, Server Actions, импортов `next/*`.

### Стили
- Tailwind CSS 4, утилити-классы. Объединяй классы через `cn()` из `lib/utils`.
- Не импортируй из `@/components/ui/*` (shadcn/ui в проекте нет).

### Доступ к данным
- Всё чтение/запись — **только через модули-стораджи**. **Не трогай
  `localStorage` напрямую из компонентов.** Это держит слой хранения
  изолированным (готовность к Supabase без переписывания UI).
- **Модель хранения (реализована):** единое хранилище `lib/artifact-store.ts` — массив
  `Artifact[]` с полями `type`, `data`, `sourceTzId`. Все артефакты (ТЗ,
  тест-чеклисты, диаграммы, протоколы, расчётчики, прототипы) живут в нём;
  происхождение — через `sourceTzId`. Существующие `tz-store`/`document-store`
  приводить к этой модели, не плодить отдельный сторадж на каждый тип.

### AI
- Все вызовы ИИ — **только через `lib/ai-providers.ts`**. Не зови SDK
  провайдеров напрямую из компонентов.
- Сохраняй существующий retry на ошибке 429 (до 2 попыток, экспон. задержка).
- Промпты живут в `lib/prompts.ts` и `lib/prompts/` — не разбрасывай их инлайн.

### Конфигурация и секреты
- Никакого хардкода ключей и путей. Только `import.meta.env.VITE_*`.
- Ключи API вводятся пользователем в настройках / берутся из env, не в коде.

### i18n
- Все пользовательские строки — через i18n. Хардкод UI-текста запрещён.
- Новую строку добавляй ключом **сразу в RU и EN** (`translations.ts`).

### Экспорт документов
- Используй существующие модули (`doc-generator`, `tz-export`) и уже
  подключённые библиотеки (`docx`, `pdf-lib`, `xlsx`, `pptxgenjs`). Новые
  библиотеки экспорта не добавляй без согласования.

### Паттерны из ТЗ (соблюдай при реализации модулей)
- **Модуль на фичу, свой UX** — не навязывай единый шаблон всем генераторам.
- **Источники входа** — переиспользуй общий `InputSourceSelector`
  (текст / готовое ТЗ / файлы / транскрипт), комбинируемо.
- **Связность ТЗ** — при пошаговой генерации передавай уже готовые блоки в
  контекст, чтобы документ читался как единое целое (единая терминология, без
  противоречий). Качество и проработка промптов — приоритет.
- **HTML-прототип** рендерь в `iframe sandbox="allow-scripts"`; интерактив (JS,
  рабочие кнопки) допускается.
- **Возврат к артефактам** — любой сохранённый артефакт открывается обратно в
  своём редакторе и дорабатывается.

### Чистота кода
- Понятные имена переменных, без «магии».
- JSDoc/комментарии к сложным функциям.
- `console.log` не должен попадать в прод — оборачивай в
  `if (import.meta.env.DEV)`.

## 5. Как добавлять фичу (рабочий цикл)

1. Найди похожий существующий модуль/экран и следуй его паттернам.
2. Логику пиши в `lib/` или `hooks/`, UI — в `components/`.
3. Данные — через стораджи, ИИ — через `ai-providers`, промпты — в `lib/prompts`.
4. Добавь i18n-ключи (RU + EN).
5. Проверь типизацию (без `any`) и сборку.
